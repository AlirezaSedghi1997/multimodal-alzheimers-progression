# راهنمای اجرای OOF stacking

نسخه: ۱۴ اکتبر ۲۰۲۶

این پیاده‌سازی برای بررسی یک پرسش مشخص تهیه شده است: آیا آموزش یک مدل ترکیب‌کننده با استفاده از تمام نمونه‌های مجازِ آموزش، به‌جای آموزش چند مدل کوچک روی زیرمجموعه‌ها، کیفیت پیش‌بینی زمان افت بالینی را تغییر می‌دهد؟

## تفاوت روش جدید با روش قبلی

در روش قبلی، برای هر شبکه یک مدل ترکیب‌کنندهٔ جداگانه ساخته می‌شد. هر مدل فقط بخشی از افراد مجموعهٔ آموزش را می‌دید. در روش جدید، خروجی‌های خارج از آموزشِ سه شبکه کنار هم قرار می‌گیرند؛ هر فرد فقط یک بار و با خروجی شبکه‌ای وارد این مجموعه می‌شود که در آموزش یا انتخاب آن شبکه حضور نداشته است. سپس یک مدل کاکس مشترک روی کل مجموعهٔ مجاز برازش می‌شود.

این کار آموزش مجدد CNN نیست. تمام خروجی‌های لازم در نسخهٔ FP32 پروژه موجود است. فقط مدل‌های کوچک کاکس دوباره برازش می‌شوند و اجرا روی CPU انجام می‌شود. برای مقایسهٔ منصفانه، روش جدید با نسخهٔ FP32 روش قبلی سنجیده می‌شود. نتایج نسخهٔ AMP مقاله خودکار تغییر نمی‌کنند.

## دستور اجرا در PowerShell

اجرای کامل:

```powershell
python -B -X utf8 'scripts\run_xyz_oof_stacking_v1.py' --mode all
```

اگر اجرای آن متوقف شد، همان دستور را دوباره اجرا کنید. بخش‌هایی که با موفقیت ثبت شده‌اند بازیابی می‌شوند. در صورت مشاهدهٔ خطای تغییر قرارداد، فایل قرارداد را حذف یا ویرایش نکنید؛ کد یا ورودی تغییر کرده و باید علت آن مشخص شود.

کنترل ورودی‌ها بدون برازش:

```powershell
python -B -X utf8 'scripts\run_xyz_oof_stacking_v1.py' --mode preflight
```

اجرای آزمایشی محدود با دادهٔ واقعی، بدون محاسبهٔ عملکرد پژوهش:

```powershell
python -B -X utf8 'scripts\run_xyz_oof_stacking_v1.py' --mode smoke
```

بررسی کامل بودن اجرای نهایی:

```powershell
python -B -X utf8 'scripts\run_xyz_oof_stacking_v1.py' --mode verify
```

نیازی به نصب کتابخانه یا فعال‌سازی دستی محیط نیست؛ دستورها مستقیماً از محیط موجود پروژه استفاده می‌کنند. درایو H باید متصل باشد. فایل‌های موقت نیز در همین درایو ساخته می‌شوند. دستور اختیاری PowerShell معادل در `scripts/run_xyz_oof_stacking_v1.ps1` قرار دارد.

## خروجی‌های اجرای کامل

- `results\xyz_oof_stacking_v1\public\REPORT.md`: گزارش خواندنیِ هفت مقایسه.
- `results\xyz_oof_stacking_v1\public\aggregate_results.json`: برآوردها، فاصله‌های اطمینان و معیارهای هر مسیر.
- `results\xyz_oof_stacking_v1\execution_status.json`: وضعیت واقعی اجرا و زمان سپری‌شده.
- `results\xyz_oof_stacking_v1\private`: مدل‌ها و اطلاعات فردی؛ این پوشه نباید منتشر شود.
- `results\xyz_oof_stacking_smoke_v1`: خروجی آزمون محدود که نتیجهٔ نهایی پژوهش محسوب نمی‌شود.

اجرا شامل چهار مسیر MRI، PET، پلاسما و تاو، پنج فولد بیرونی، سه بذر، و در مجموع ۱۸۰ مدل کاکس است. برای فاصله‌های اطمینانِ اختلاف IBS، چهل هزار بازنمونه‌گیری جفتی داخل فولدها انجام می‌شود. خواندن checkpointها برای تطبیق هش و زمان پردازش آماری به سرعت درایو و بار سیستم بستگی دارد. اجرای محدود معیار قابل اتکایی برای زمان دقیق اجرای کامل نیست؛ زمان واقعی در فایل وضعیت ثبت می‌شود.

## چگونه نتیجه را بخوانید؟

IBS کمتر بهتر است. اختلاف منفی یعنی مدل افزوده در همین ارزیابی خطای کمتری داشته است. اگر فاصلهٔ اطمینان اختلاف شامل صفر باشد، بهبود پایدار با این تحلیل اثبات نشده است. نتایج مثبت و منفی هر دو حفظ می‌شوند. عدد C-index نیز گزارش می‌شود، اما در این نسخه فاصلهٔ اطمینان جدیدی برای آن محاسبه نمی‌شود.

سه پرسش باید جدا بمانند: ارزش افزودن MRI/PET؛ ارزش افزودن نشانگرها؛ و اثر تغییر روش ترکیب از مدل‌های کوچک به مدل مشترک. بهتر شدن روش ترکیب به‌تنهایی اثبات نمی‌کند که تصاویر نسبت به اطلاعات بالینی ارزش افزوده دارند. در مقابل، نبود تفاوت معنی‌دار هم به معنی بی‌ارزش بودن پژوهش نیست؛ این آزمایش مستقیماً یکی از ایرادهای روش‌شناختی داوری را بررسی می‌کند.

جزئیات روش، فرض‌ها و حدود تفسیر در `docs/OOF_STACKING_V1_PROTOCOL.md` ثبت شده است. این دستورها مقاله را ویرایش نمی‌کنند و هیچ فایلی به GitHub ارسال نمی‌کنند.
